# Update LLM Service Layer & Protocols Implementation Plan

## Overview
This plan outlines the steps to introduce `GenerationParameters` into the LLM service layer, ensuring that parameters like temperature, max tokens, and top-p are correctly passed from the configuration down to the individual LLM providers (OpenAI, Ollama, OpenRouter).

## Scope Definition (CRITICAL)
### In Scope
- Define `GenerationParameters` struct in `MonadShared`.
- Update `LLMChatRequest` and `LLMPromptRequest` in `MonadCore`.
- Update `LLMClientProtocol` and `LLMServiceProtocol` in `MonadCore`.
- Update `LLMService` and all provider clients (`OpenAIClient`, `OllamaClient`, `OpenRouterClient`).
- Update `UnconfiguredLLMService` in `Sources/MonadCore/Dependencies/LLMDependencies.swift`.

### Out of Scope (DO NOT TOUCH)
- Modifying `ChatEngine` or other high-level orchestration logic.
- Adding new LLM providers.
- Changing persistence logic for `LLMConfiguration`.

## Current State Analysis
- `LLMConfiguration` and `ProviderConfiguration` already contain fields for `temperature`, `maxTokens`, `topP`, `frequencyPenalty`, and `presencePenalty`.
- These fields are currently not passed through the protocols (`LLMClientProtocol`, `LLMServiceProtocol`).
- `LLMService` coordinates between providers but doesn't pass these parameters to the clients.
- `OllamaClient` uses a custom request structure that lacks these options.

## Implementation Phases

### Phase 1: Shared Models
- **Goal**: Define the centralized `GenerationParameters` struct.
- **Steps**:
  1. [x] Create `Sources/MonadShared/SharedTypes/GenerationParameters.swift`.
  2. [x] Update `ProviderConfiguration.swift` to include a `generationParameters` computed property for convenience.
- **Verification**: `swift build` in `MonadShared`.

### Phase 2: Protocol Updates
- **Goal**: Update the core LLM protocols to accept `GenerationParameters`.
- **Steps**:
  1. [x] Update `LLMChatRequest` and `LLMPromptRequest` in `Sources/MonadCore/Services/LLM/LLMServiceProtocol.swift`.
  2. [x] Update `LLMClientProtocol` in `Sources/MonadCore/Services/LLM/LLMService.swift`.
  3. [x] Update `LLMServiceProtocol` in `Sources/MonadCore/Services/LLM/LLMServiceProtocol.swift`.
- **Verification**: `swift build` (expecting failures in implementations).

### Phase 3: Client Implementations
- **Goal**: Update provider-specific clients to use the new parameters.
- **Steps**:
  1. [x] Update `OpenAIClient.swift`: Pass parameters to `ChatQuery`.
  2. [x] Update `OllamaModels.swift`: Add `options` to `OllamaChatRequest`.
  3. [x] Update `OllamaClient.swift`: Pass parameters to the `options` field.
  4. [x] Update `OpenRouterClient.swift`: Pass parameters to `ChatQuery`.
- **Verification**: Clients compile correctly.

### Phase 4: Service Implementation & Dependency Placeholder
- **Goal**: Update the coordinator and the unconfigured placeholder.
- **Steps**:
  1. [x] Update `LLMService.swift`: Extract parameters from `configuration` and pass them to clients.

  3. [x] Update `MockLLMService` in `Tests/MonadTestSupport/MockLLMService.swift`.
