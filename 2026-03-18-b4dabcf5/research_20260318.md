# Research: Expose Generation Parameters in MonadCore Facade

**Date**: 2026-03-18

## 1. Executive Summary
The `GenerationParameters` struct exists in `MonadShared` and is supported by `LLMService` and its underlying providers. However, these parameters are not exposed through the `MonadCore` facade, nor are they propagated through `ChatEngine` and `ChatTurnContext`. This prevents users of the library from customizing LLM generation settings (like temperature, max tokens, etc.) on a per-request basis.

## 2. Technical Context
- **GenerationParameters**: Defined in `Sources/MonadShared/SharedTypes/GenerationParameters.swift`. Contains properties for `temperature`, `maxTokens`, `topP`, `frequencyPenalty`, `presencePenalty`, and `seed`.
- **LLMService**: `Sources/MonadCore/Services/LLM/LLMService+Stream.swift` already supports `GenerationParameters` in its `chatStream` method. It falls back to `configuration.generationParameters` if none are provided.
- **ChatTurnContext**: `Sources/MonadCore/Services/Chat/ChatTurnContext.swift`. This immutable snapshot is used by pipeline stages but currently lacks a `generationParameters` property.
- **LLMStreamingStage**: `Sources/MonadCore/Services/Chat/Stages/LLMStreamingStage.swift`. This stage calls `llmService.chatStream` but passes `nil` for `generationParameters` (implicitly via default parameter value).
- **ChatEngine**: `Sources/MonadCore/Services/Chat/ChatEngine.swift`. The `execute` method does not accept `generationParameters`.
- **MonadCore**: `Sources/MonadCore/MonadCore.swift`. The public `run` method does not accept `generationParameters`.

## 3. Findings & Analysis
- **Propagation Gap**: The infrastructure for generation parameters is mostly in place at the service level, but the orchestration layer (`ChatEngine`) and the context object (`ChatTurnContext`) are missing the necessary fields to carry these parameters from the public API down to the pipeline stages.
- **MonadCore Initializers**: The facade initializers could also benefit from an optional default `GenerationParameters` object, although the `LLMConfiguration` already provides some defaults.
- **ChatEngine.prepareSession**: This method in `Sources/MonadCore/Services/Chat/ChatEngine+ContextBuilding.swift` is responsible for initializing `ChatTurnContext`, so it must be updated to handle `GenerationParameters`.

## 4. Technical Constraints
- `ChatTurnContext` is a `Sendable` struct, so any added properties must also be `Sendable`. `GenerationParameters` is already marked as `Sendable`.
- `TurnOutputs` (an actor) does not need to hold `GenerationParameters` as they are input parameters for the turn, not outputs.

## 5. Architecture Documentation
- **Pipeline Pattern**: The chat execution follows a pipeline pattern where a `ChatTurnContext` is passed through multiple `PipelineStage`s.
- **Facade Pattern**: `MonadCore` acts as the primary entry point for the library, hiding the complexity of `ChatEngine` and dependency injection.
- **Dependency Injection**: The project uses `swift-dependencies` for internal service resolution.
