# Research: Update Configuration Types

**Date**: 2026-03-18

## 1. Executive Summary
The task is to add optional LLM parameters (`temperature`, `maxTokens`, `topP`, `frequencyPenalty`, `presencePenalty`) to the configuration models used across the Monad system. Currently, `ProviderConfiguration` and `LLMConfiguration` lack these properties. Adding them will allow more granular control over LLM behavior.

## 2. Technical Context
- **Affected Files**:
    - `Sources/MonadShared/SharedTypes/ProviderConfiguration.swift`: Defines the per-provider configuration.
    - `Sources/MonadShared/SharedTypes/LLMConfiguration.swift`: Defines the global configuration, which includes a dictionary of `ProviderConfiguration` and computed properties for the active provider.
- **Current implementation details**:
    - `ProviderConfiguration` has properties for `endpoint`, `apiKey`, `modelName`, etc. (Sources/MonadShared/SharedTypes/ProviderConfiguration.swift:3).
    - `LLMConfiguration` acts as a wrapper and manager for multiple `ProviderConfiguration` instances (Sources/MonadShared/SharedTypes/LLMConfiguration.swift:5).
    - `LLMConfiguration` uses computed properties to expose fields from the active provider for backward compatibility (Sources/MonadShared/SharedTypes/LLMConfiguration.swift:12).

## 3. Findings & Analysis
- `ProviderConfiguration` is a `Codable`, `Sendable`, `Equatable` struct.
- `LLMConfiguration` is also `Codable`, `Sendable`, `Equatable`.
- Both have custom `init(from decoder: Decoder)` to handle default values and evolution.
- `LLMConfiguration` has two main initializers: one for the full multi-provider structure and a "legacy" flat initializer.
- `ConfigurationStorage` handles saving/loading and migration from older versions (Sources/MonadServer/Services/Configuration/ConfigurationStorage.swift).

## 4. Technical Constraints
- Changes must maintain compatibility with existing serialization/deserialization.
- The new properties should be optional (`?`) to avoid breaking existing configurations that don't have them.
- Initializers should be updated to support these new properties while providing reasonable defaults (nil).

## 5. Architecture Documentation
- The project uses a multi-provider configuration pattern where `LLMConfiguration` tracks an `activeProvider` and a dictionary of `providers: [LLMProvider: ProviderConfiguration]`.
- Backward compatibility is maintained via computed properties in `LLMConfiguration` that proxy to the `activeProvider`.
- Types are shared across Server, Client, and CLI via the `MonadShared` module.
