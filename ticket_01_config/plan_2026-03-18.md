# Update Configuration Types Implementation Plan

## Overview
Add optional LLM parameters (`temperature`, `maxTokens`, `topP`, `frequencyPenalty`, `presencePenalty`) to `ProviderConfiguration` and `LLMConfiguration` to allow more granular control over LLM behavior.

## Scope Definition (CRITICAL)
### In Scope
- Add 5 new optional properties to `ProviderConfiguration`.
- Update `ProviderConfiguration` initializers and `Codable` logic.
- Add computed proxy properties to `LLMConfiguration`.
- Update `LLMConfiguration` initializers.

### Out of Scope (DO NOT TOUCH)
- UI updates in `ConfigurationScreen.swift`.
- Service-level implementation of these parameters (this is just the model update).
- Any changes to `ToolCallFormat` or other configuration fields.

## Current State Analysis
- `ProviderConfiguration.swift:3` defines the per-provider configuration.
- `LLMConfiguration.swift:5` defines the global configuration.
- `LLMConfiguration` uses computed properties for backward compatibility and convenience.

## Implementation Phases

### Phase 1: Update ProviderConfiguration
- **Goal**: Add new properties and update `Codable` support in `ProviderConfiguration`.
- **Steps**:
  1. [x] Add `temperature: Double?`, `maxTokens: Int?`, `topP: Double?`, `frequencyPenalty: Double?`, `presencePenalty: Double?` to `ProviderConfiguration` in `Sources/MonadShared/SharedTypes/ProviderConfiguration.swift`.
  2. [x] Update `init(...)` in `ProviderConfiguration` to include these new properties with default value `nil`.
  3. [x] Update `init(from decoder: Decoder)` to decode these new properties using `decodeIfPresent`.
- **Verification**: `swift test --filter MonadCoreTests.LLMConfigurationModelsTests`

### Phase 2: Update LLMConfiguration
- **Goal**: Add proxy properties and update initializers in `LLMConfiguration`.
- **Steps**:
  1. [x] Add computed properties for the 5 new parameters in `Sources/MonadShared/SharedTypes/LLMConfiguration.swift` (similar to `endpoint`, `apiKey`, etc.).
  2. [x] Update the main `init(...)` in `LLMConfiguration` (if needed, though it seems it might not need it since it mostly handles providers). Actually, `LLMConfiguration` has a "legacy" flat `init`.
  3. [x] Update the legacy `init(...)` in `LLMConfiguration` to accept the 5 new parameters and pass them to the `activeProvider`'s `ProviderConfiguration`.
- **Verification**: `swift test --filter MonadCoreTests.LLMConfigurationModelsTests`

### Phase 3: Final Verification
- **Goal**: Ensure no regressions and all tests pass.
- **Steps**:
  1. [x] Run all related tests: `swift test --filter LLMConfiguration`.
  2. [x] Ensure the server still builds: `swift build`.
- **Verification**: `swift build && swift test --filter LLMConfiguration`
